Analogy

Raw = you take a photo of every page of a patient's file. Exact copy, nothing changed.
Bronze = you type each page into a spreadsheet. Same info, structured format.
Silver = you clean the spreadsheet: fix typos, remove duplicates, track what changed over time.
Gold = you create a summary dashboard that doctors actually look at. Only current info, easy to read.

SCD Type 2 Explained

How Changes Are Tracked
Analogy

Think of a patient's address history. When they move from Bangalore to Mumbai, we don't overwrite Bangalore. We mark Bangalore as "old address" with an end date, and add Mumbai as "current address" with a start date. Both rows exist. You can always look back and see where they lived at any point in time.

Initial Load (Day 1)

resource_idcityeffective_fromeffective_tois_current
patient-001Bangalore2026-10-109999-12-31true

One row. One version. Current.

Day 3: Patient Moved to Mumbai

resource_idcityeffective_fromeffective_tois_current
patient-001Bangalore2026-10-102026-10-12false
patient-001Mumbai2026-10-129999-12-31true

Two rows. Old version expired (is_current=false). New version is current. History preserved.

How Change Detection Works

StepWhat Happens
1Compute SHA256 hash of entire resource JSON (content_hash)
2Compare incoming content_hash with current Silver row's content_hash
3aSame hash = unchanged. Do nothing.
3bDifferent hash = changed. Expire old row (is_current=false, set effective_to). Insert new row (is_current=true).
3cNo existing row = new resource. Insert as current.

Scheduling & Orchestration

Databricks Workflow (workflow.json)

The pipeline is operationalized through a Databricks Workflow defined in config/workflow.json. This wraps the notebook into a scheduled, monitored, auto-retrying production job.

Idempotency Guarantee

LayerRe-run BehaviorDuplicates?
RawOverwrites same file pathNo
BronzeMERGE skips existing rowsNo
SilverSCD2 skips unchanged recordsNo
GoldCREATE OR REPLACE rebuilds viewNo

Safe to retry, re-run manually, or overlap with scheduled run. Zero data corruption.

How to Activate

Option A (UI): Workflows -> Create Job -> JSON toggle -> paste workflow.json -> Create -> toggle PAUSED to UNPAUSED

Option B (CLI): databricks jobs create --json @workflow.json then databricks jobs update {id} --json '{"schedule":{"pause_status":"UNPAUSED"}}'

Manual trigger: In UI click "Run Now", or CLI: databricks jobs run-now {id}
